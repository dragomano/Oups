# AGENTS.md — Oups

Cross-platform reminders app in the spirit of Wise Reminder: popups at a given time, recurrence, snooze, priorities, tray, autostart. Windows ships as a portable folder — exe + `locales/` + SQLite DB, no installer; macOS and Linux get their normal bundles (.app/.dmg, .deb/AppImage). The optional `oups.wav` sound and the Windows 11 backdrop are Windows-only. Version: see `src-tauri/Cargo.toml`.

## Stack

- **Frontend**: Svelte 5 (runes) + TypeScript + Vite, plain CSS (custom properties, light/dark). One entry, `index.html`, serves every window: the frontend picks the component from the Tauri window label (`main`, `editor`, `settings`, `reminder-*`, `missed`) via `src/lib/window-role.ts`, and `src/main.ts` mounts it through a dynamic import (one chunk per role).
- **Backend**: Rust + Tauri 2 (`tray-icon`), plugins `single-instance`, `autostart`, `dialog`, `opener`; `rusqlite` (bundled), `chrono`, `serde`, `serde_json`, `uuid`, `tokio` (time), `sys-locale` (first-run language detection), `window-vibrancy` (Windows only, Mica).
- **Tooling**: pnpm, Biome (TS/JS/JSON), svelte-check, Vitest, cargo fmt/clippy/test.

## Hard rules

1. **Single source of truth for name/version.** Version lives ONLY in `src-tauri/Cargo.toml`. Never add `version` to `package.json` or `tauri.conf.json` (Tauri falls back to Cargo; `dist.mjs` reads Cargo too). Display name lives only in `tauri.conf.json` (`productName`); Cargo package `scheduler` is a technical identifier, not a second name.
2. **English only in source** (comments, identifiers, logs, doc text in Rust/TS/Svelte). User-facing strings are never hardcoded: use `locales/*.json` via `t("dotted.key")` or `locale::tr()`. The product name is NOT translatable and never goes into locale files. User docs ship as `README.md` and `README.ru.md`.
3. **Tests are mandatory** for pure logic (recurrence, scheduling decisions, pluralization, parsing, matrix, i18n fallback). Rust: in-file `#[cfg(test)] mod tests`; TS: `src/**/*.test.ts`. Bug fix = regression test. UI logic that needs testing moves from `.svelte` into `src/lib/*`.
4. **Biome governs TS/JS/JSON style** (`pnpm lint`, `pnpm lint:fix`). `.svelte` files are excluded (Biome can't parse them); svelte-check covers them. After a Biome upgrade run `pnpm biome migrate --write` if the config warns.
5. **Every task ends with `pnpm check:all` green.** Never hand the turn back with a red check. Run `cargo fmt` before committing Rust.
6. **Split code by concern.** One Svelte file / Rust module = one concern. Extract if a file passes ~400 lines or mixes concerns. Shared logic goes to `src/lib/*` or its own Rust module, not into the component that happens to need it.
7. **Theming contract.** Settings persisted in the `settings` table, editable in Settings:
   - `theme`: `system` | `dark` | `light` → `<html data-theme>`; `system` removes the attribute and follows `prefers-color-scheme`.
   - `accent`: `red` | `orange` | `amber` | `green` | `teal` | `cyan` | `blue` | `violet` | `pink` → `<html data-accent>`. Palette is systematic, never hand-picked: constant OKLCH lightness/chroma `0.55 0.155`, hues every 40° starting at 10° (red). A new accent must keep the 40° grid and be added to `app.css`, `theme.ts (ACCENTS)`, `settings.rs (ACCENTS)`, `Settings.svelte (ACCENT_COLORS)` and both locale files. `theme.ts::applyTheme` is called on mount by both the main window and popups.
   - `popup_corner`: 3×3 positions (`top-left`, `center-top`, `top-right`, `center-left`, `center`, `center-right`, `bottom-left`, `center-bottom`, `bottom-right`; default `bottom-right`). Popups stack like a card deck shifted toward screen center (`scheduler.rs::popup_origin`, work area of the monitor under the cursor). Settings shows a 3×3 grid mirroring the screen.
   - **Never hardcode colors** in components; use `--accent`, `--accent-hover`, `--accent-soft`, `--panel`, `--text`, etc.
8. **Binary size matters.** Release profile: `opt-level = "s"`, `lto`, `codegen-units = 1`, `panic = "abort"`, `strip`. `dist.mjs` runs UPX (`--best --lzma`) when on PATH (some antivirus flags UPX-packed exes). No heavyweight dependencies for small conveniences; keep tests and release build lean.
9. **Locales: resilience and self-description.**
   - English is embedded at compile time (`locale.rs`, `include_str!` of `locales/en.json`; keep the two in sync — same file at build time). Lookup: external `locales/<lang>.json` → external `locales/en.json` → embedded English. Deleting `locales/` degrades the UI to English; it never breaks and never shows raw keys. `get_locale` uses the same fallback.
   - Each file has `meta`: `{ code, name, dir, plural_forms?, unit_genders? }`. `code` must match the file name. `dir` (`ltr`/`rtl`) is applied to `<html>` on load — set it in the file, never in code.
   - The language list is always derived from the folder (`locale::available()` / `list_locales`); never hardcode language codes in settings, UI or validation. Adding a language = dropping `xx.json` with `meta` next to the exe.
   - First run detects the system language (`sys-locale`): full regional code first, then base language, only if a matching locale exists; the choice is persisted and stays stable.

## Domain notes (don't re-derive)

- **Timestamps** are local wall-clock `YYYY-MM-DDTHH:MM:SS`; lexicographic order = chronological, the scheduler relies on it.
- **UI clock.** Everything derived from "now" (relative label "in 23 hours", matrix overdue/urgent) reads `src/lib/clock.svelte.ts`, never `Date.now()` in a component. Display only: the list refreshes via the `reminders-changed` event, no polling.
- **Priority** has four levels `low|normal|high|critical`, stored as -1/0/1/2 (the original two kept their codes, so no migration). Matrix treats `high`+`critical` as "important". Priority colors live once in `app.css` (`.prio-*`), shared by list, matrix, picker and popup — don't redeclare per component. Icons: the three chevrons are INDICATORS, sized 18 with `strokeWidth={2.5}` (16 in the matrix), so they do not read as controls; `normal` is a plain `Circle`. The picker's open list centers each icon like the closed button does.
- **Eisenhower matrix.** Quadrant comes from ONE axis: importance = priority (picked or dragged). `quadrantOf()` is `BY_PRIORITY[priority]`; the schedule plays no part (a reminder five years out sits with an overdue one; test "ignores the schedule entirely" pins this). Urgency affects ORDER and LOOK only: `dueKind()` marks overdue/within `URGENT_WINDOW_MS` (24 h) as urgent; no `next_due` is never urgent; `compareByDue()` floats urgent items to the top of a quadrant. Do NOT "fix" this into a real 2-axis grid without changing tests and rethinking the layout. `QUADRANTS` order `do, delegate, schedule, drop` = 2×2 grid top-left → bottom-right. Only active reminders appear. Sorting is pure, in `matrix.ts`, tested. `dueKind()` is the single definition of "overdue"; the list reuses it. Header icons are Lucide components in `META` (flame, hourglass, calendar-clock, coffee), each tinted like its block's left stripe — `drop` uses `--muted`, its stripe color `--border` would be near invisible on the header panel.
- **Reminder list layout.** Full window width, no max column. The row is a named-area grid at all widths (`grid-template-areas: "dot title when" / "dot meta when" / "dot note actions"`): title+recurrence live in the left block and the title wraps there, "Next run" sits top-right, the note takes the free middle cell, and the action buttons are pinned bottom-right. The note is a DIRECT child of `.row` (not of `.meta`) — the only way to keep it in its own grid cell without dragging the recurrence along. It renders even when empty so the action cell keeps its bottom alignment. The high/critical stripe is `border-left: 3px` paired with `padding-left: 12px` (= a plain row's `1px + 14px`), so titles of striped and plain rows start at the same x — widening the border alone drifts the text 2px right. Overdue = `--danger` + bold + tinted row, matching the matrix's `.qtime.overdue`.
- **Toolbar layout.** `toolbar-layout.ts` chooses the layout from measured natural widths, not fixed viewport breakpoints. Keep all controls including search on one row while they fit; otherwise put search below, then hide the New reminder label, then the Import/Export labels as needed. The two-row grid never wraps individual buttons. Icon-only buttons stay 30px squares. An inert off-screen probe uses the same markup, and ResizeObserver remeasures on resize or locale/font changes. The bar holds the app's actions only: the view tabs and the window's caption buttons live in the title strip above it, so the row has four parts (new, search, import/export, settings). The strip's own parts are never dropped either, so the narrowest window has to hold the densest row of the widest locale AND the strip — `minWidth` is 660, and tests derive both bounds from `tauri.conf.json`.
- **Main window chrome.** The main window is frameless (`decorations: false` in `tauri.conf.json`) and transparent (`transparent: true`), so the Windows 11 system material can show through it: `backdrop.rs` asks the desktop window manager for Mica and reports whether the system has it. Tauri's default `shadow: true` still gives the window the rounded corners, the drop shadow and the 1px frame, and tao's invisible resize border keeps edge dragging, snapping and Win+Arrow working. The app draws its own frame on top of the material: in `App.svelte` `.frame` is the gutter marked `data-tauri-drag-region="deep"` (the chrome drags from anywhere) and transparent in Mica mode, so the material IS the window's edge; `.card` is the bordered, rounded surface that clips the toolbar's corners, and `.content` is marked `data-tauri-drag-region="false"` so rows stay clickable. The layers are variables, not component colors: — `--frame-bg`, `--card-bg`, `--titlebar-bg` and `--toolbar-bg` are solid by default and translucent under `:root[data-backdrop="mica"]`, and `theme.ts::applyBackdrop` sets that attribute from the `window_backdrop` command (asked before the window is revealed, so the first frame is already final). An older Windows has no material, and macOS/Linux never have one: the command answers false and the layers stay solid. The window's title strip (`TitleBar.svelte`) sits inside the card, 40px tall: the app icon and the display name on the left (`productName` through the `app_name` command — the name is not translatable and never goes into a locale file), the view tabs in the middle, the caption buttons on the right. The tabs left the toolbar for it, so the toolbar keeps only the app's actions; the caption buttons (`WindowControls.svelte`) are 28px squares with a quiet fill under the pointer. Window actions go through `commands.rs::window_control` / `window_maximized` rather than the JS window API, so no capability is involved; `window_maximized` is re-read on `tauri://resize` because the state also changes from a double click on a drag region, Win+Arrow and snapping. The native title (`tauri.conf.json`) stays for the taskbar, Alt+Tab and the system menu. Snap *layouts* (hovering the maximize button) need a custom hit test and are not available on a frameless window — accepted.
- **Icon buttons.** All UI icons are Lucide SVGs via `@lucide/svelte` (deep imports `@lucide/svelte/icons/<name>` keep tree-shaking); the tray menu uses the same glyphs pre-rendered to PNG by `pnpm tray-icons` (`scripts/tray-icons.mjs`, output committed under `src-tauri/icons/menu/`) — native menus cannot use Svelte components, and the package does not ship an `export` icon (reserved word), so Import/Export use `arrow-down-to-line`/`arrow-up-from-line`. Icon-only buttons are a FIXED square (`button.icon`) — never let the icon size the box, and keep its `flex: none`: a flex item with a definite width still shrinks to its content, which is how the off-screen probe came to measure a 30px button as 18px and quietly weakened every toolbar decision. An SVG centers itself inside a flex box, so no per-glyph ink corrections exist anymore; do not reintroduce `--icon-shift`-style hacks for text glyphs, add another Lucide icon instead. But a bare inline SVG sits on the text baseline and rides above the label (checked on the Import/Export buttons), so any button mixing icon and text (`new-btn`, `.io`, matrix header icons) is `display: inline-flex` with `align-items: center`. Popup priority badges reuse `priority.badge.*` — no separate `popup.*_priority` keys in the locales. A close button (`button.close` in `app.css`) hovers red with a white glyph, and that one rule is the caption's red hover for every window: the main window's close, the settings modal and the editor. The caption buttons keep the fixed box too (28px squares in `WindowControls.svelte`): the glyph never sizes it. Keep the caption's own rules off the hover state: the neutral fill is scoped to `.caption .cap-btn:not(.close):hover`, so the close button keeps the shared red hover — a scoped rule left on `:hover` outranks the shared one and would leave the glyph grey on red.
- **Editor window.** A separate owned WebView (label `editor`) uses an independent draft and opens up to 820 logical pixels wide, fitted to the monitor work area rather than the main window. Existing drafts are focused instead of overwritten by another edit action. The native title bar is hidden; the internal header provides a drag region and a close button. Theme, locale and content load before the first reveal. `EditorWindow` observes the natural header/form/footer height; the backend caps it to the work area including native decorations. The form uses two columns above 700px, one column at/below 700px; `MonthDayPicker` replaces the inline month grid with a native popover on narrow screens. Only `.editor-content` scrolls when necessary; footer actions stay visible. `PriorityPicker` uses fixed positioning and the month grid uses the top layer, so neither is clipped by the scroll container; `floating-panel.ts` fits both to the viewport. The editor never blocks a past start: the date field gets `min={todayStr()}` for NEW reminders only (editing imported, spent or back-dated records must stay possible), and every ambiguous case is a hint, not a validation error (`isPastDateTime` in `time.ts`; seconds ignored, so "today at the current minute" is not past). Hints: a one-shot already behind the clock fires right after saving; end date before start or a used-up repeat count means no next run. `save()` writes `endMode: never` for `once` (that section is hidden; a stale rule must not leak to the backend).
- **Settings modal.** Settings and the editor are native owned WebViews created and fitted through the same `modal_window.rs` helper. The main window is disabled until the child is destroyed, so the window manager supplies modal feedback; there is no DOM backdrop or custom animation. Only one modal is opened at a time. Both windows hide the system title bar and provide an internal drag region and close button; Escape also closes them. Settings keep two columns above 560px and stack below it, with a centered position caption. Only the settings body scrolls; the autosave note remains visible. Behavior labels toggle their native inputs, and settings save immediately.
- **Launch geometry.** The main window does not open at a fixed size: `window_size.rs` sizes it for the work area of the monitor under the cursor (taskbar excluded, everything in logical pixels, so display scaling takes care of itself) and centers it there. It runs from `setup`, which Tauri calls after the config windows exist but before anything can reveal them. The config's `width`/`height` stay the reference — what a 1920×1080 screen with a taskbar gets; a roomier work area grows the window (one factor for both axes, capped at 1.5×, so an ultrawide does not stretch it), a tighter one shrinks it to fit, leaving `EDGE` px of desktop around it. `center: true` in the config stays as the fallback for the no-monitor-info case. `initial_size` is pure and tested against a table of screens, including 125%-scaled laptops. One trap, found by measuring the real window: tao turns a requested inner size into a window size by adding the frame it measures, and a window that has never been shown still reports the frame it was created with (caption height included), so the first `set_size` lands ~40px too tall — the call is repeated until the size holds, which takes two passes.
- **Recurrence.** `advance_after_fire` computes the next occurrence from the fired slot (stored `next_due`), not from "now" — this is why snooze doesn't shift interval grids. Don't "simplify" it to `now`. `initial_next_due` applies the end mode at creation exactly as `advance_after_fire` does after a fire: `Until` is an inclusive calendar-date bound (shared helper `until_allows`); `AfterCount { n }` is spent once `fired_count >= n`. A rule with nothing left keeps `next_due = NULL` and stays enabled (not marked completed). Imports always start with `fired_count = 0`, so imported rules keep their occurrences.
- **Popups.** One window per reminder (`reminder-<id>`); the scheduler skips creation if it exists but always advances the recurrence. Overdue reminders at startup collapse into one `missed` window (snapshots in `AppState.missed`). Dismissing needs no DB write (completion/next occurrence is written at fire time). Snooze rewrites `next_due` and closes the window. Unlike the main window they keep their native title bar: a popup is grabbed and closed by the system chrome, and the frame there would cost more room than it is worth.
- **Startup.** App windows that load a page are created hidden so the WebView never shows a blank or wrongly themed first frame: the main window via `tauri.conf.json` `visible: false`, popups via `.visible(false)` in `scheduler.rs::build_popup_window`. The frontend reveals its window at the end of `onMount`, after theme, language and data are in place: `App.svelte` calls `api.mainWindowReady()`, `Popup.svelte` calls `api.popupWindowReady()` (the command checks the label: `reminder-<id>` or `missed`). An autostart launch (`--autostart`, detected once into `startup.rs::Launch`) keeps the main window hidden for good — the app starts in the tray; popups always show. A fallback (`startup.rs::fallback_reveal`, 10 s `READY_FALLBACK`) reveals a still-hidden window if the page never loads — for the main window it is skipped on autostart launches.
- **Wise Reminder *.dat import** (`wise.rs`): PERIOD 0 = once (ENDTIME set → completed), 3 = monthly (REPEAT_DATA byte i == 0x01 selects day i+1), 4 = yearly (year/month/day from the REPEAT_DATA double). REPEAT_DATA bytes 7..15 = little-endian f64 TDateTime (days since 1899-12-30) of the scheduled date; WAKETIME = scheduled time of day; LASTTIME = last actual fire; dates are local wall-clock; titles are CP1251. Keep in sync with tests (fixture `src/testdata/wise-sample.dat`).
- **Wise Reminder 2.x *.wrm import** (`wrm.rs`): UTF-8 JSON envelope, PascalCase records. `Date`+`Time` → start_at; `Description` → note. `Repeat`: Never→once, Hourly→every hour, Daily, Weekdays→Mon..Fri, Weekends→Sat+Sun, Weekly (`SelectedWeekdays`), Monthly (`SelectedMonthDays`), Quarterly→every 3 months, SemiAnnually→every 6 months, BiWeekly→every 2 weeks, Yearly, Custom (`CustomInterval` × `CustomUnit`); unknown → once. `RepeatEnd` OnDate → Until (date part of `RepeatEndDate`, may carry a UTC offset). Only `Priority: High` maps to high. `IsCompleted` → completed. `CreatedAt`/`UpdatedAt` are RFC3339 UTC, converted to local wall-clock. Records that fail to parse are skipped. Fixture: `src/testdata/wise-sample.wrm`.
- **Pluralization is locale data, not code.** `every_many.<unit>` holds declined forms separated by `|`; `meta.plural_forms` maps each CLDR category to a slot (`ru`/`uk`: one/few/many; `ar`: all six incl. dual; `en`/`de`/`es`: one/other). Category comes from `Intl.PluralRules` (built-in, not a dependency) via `plural.ts::pluralSlot`; `time.ts::declinedWord` is the single entry point for any `"|"`-separated word (`formatUnit` is a thin wrapper over it). The editor's repeat count is such a word too: `end.count_noun` holds the noun written AFTER the number, so the numeral sits next to the input. `end.after` sets its case — a preposition drags the numeral into the same case, so only ONE count keeps the singular (`После 1 повтора`) and every other count goes plural. Hence `"повтора|повторов|повторов"` for `ru`: the shared table has four slots, so a form is repeated where categories collapse. CLDR counts the bare cardinal, which a case-governed position may not agree with (`pl` "many" claims 21) — such a reading has no category to live in. No language is special-cased in code: a file declaring nothing keeps "form for one | form for everything else"; a forgotten category falls back to slot 1. Gender agreement (`Каждый 21 час` / `Каждую 21 минуту`) needs `meta.unit_genders` plus `editor.every_m` / `editor.every_f`; `uk` shares `ru`'s categories but declares its own genders (`година` f., `тиждень` m. — opposite of `час`/`неделя`), which is why genders live in the file. Labels put the numeral in the middle (`"{prefix} {n} {unit}"`); a language ordering it differently needs `recurrenceText` reworked. `plural.test.ts` covers the engine, fallbacks and every shipped locale (self-description, slot ranges, key parity with `en.json`, `{placeholder}` parity).
- **Demo templates** (`demo/*.json`) use RELATIVE timestamps ("+2h", "-6d19h": sign + d/h/m), resolved in `relative.rs::resolve_reminder`, called from `insert_imported` BEFORE `sanitize` (which replaces an unrecognized `startAt` with now). Absolute dates rot: a past one-shot fires on the next tick and completes. Export always writes absolute stamps; the reader accepts both. `pnpm demo` then runs `biome check --write demo` to keep committed files formatted.
- **Screenshots** (`screenshots/*.png`, app windows 1194×834, tray menu 460×360, the two narrow shots 390×844, `.en` + `.ru`) are generated, never hand-edited or screenshotted from the running app: `pnpm shots` drives headless Edge over the DevTools protocol against `_shots/`, which mounts the REAL components with `@tauri-apps/*` aliased to stubs. The data is the demo set — `_shots/dataset.ts` ports the import path (`relative::resolve_reminder` then `initial_next_due`) against a pinned `Date.now()`, so the relative labels are reproducible; `completed`/`enabled` (the two fields the JSON reader resets) are the only ones the harness sets itself. Three traps, all of which produced wrong output at least once: `msedge --screenshot` measures the WINDOW not the viewport, so use `Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot`; capture only after the page raises `data-shots-ready`, never after a fixed delay; and give every window its own iframe, because `100vh` in one document is the canvas and pushes the popup off it. Details in `screenshots/README.md`. The main-window shots include the app's own window chrome (the frame, its gutter, the title strip and the caption buttons) — the harness stubs `window_maximized` with `false`, so the caption shows maximize. It stubs `window_backdrop` with `false` as well: a browser has no system material behind it, so the shots show the solid layers. The empty-state shot (`06`) is kept in the gallery but deliberately left out of both READMEs.
- **Storage.** All settings and reminders live in `reminders.db` — never the registry. The ONLY registry write is the optional autostart entry (HKCU …\Run, via tauri-plugin-autostart). `paths.rs` picks the folder: the project root in dev, the exe folder in a release build when it is writable (the portable layout), and the platform app-data dir otherwise (`%LOCALAPPDATA%\Oups`, `~/Library/Application Support/Oups`, `$XDG_DATA_HOME/Oups`) — installed .deb/.dmg builds put the binary where it is not writable. Locales are looked up next to the exe first, then in the bundle resource dir, then in the project root in dev. A Windows portable folder has to be writable: unpack it anywhere but Program Files, or the data silently moves to `%LOCALAPPDATA%\Oups`.
- **Sound.** `sound.rs` plays `oups.wav` through `PlaySoundW` when a reminder fires; the file is optional and lives next to the exe (`paths.rs::sound_path`). A missing, unreadable or unsupported file is silently skipped, and playback never affects scheduling. Windows only — the other platforms have no sound path at all.
